# Architecture and grain

Local raw CSVs stay private. The original 53 order fields and eight access-log fields are uploaded into `staging.DataCoRaw` and `staging.DataCoAccessLogs` as text. SQL Server uses `TRY_CONVERT` to create typed `clean.order_items` and `clean.access_events`, checks keys, dates, quantities, financial identities and order-field consistency, then populates `analytics.fact_order_items`, `analytics.fact_orders` and daily `analytics.fact_product_views`. `python/after_sql.py` reads those SQL facts, computes RFM/cohorts/product interest, saves local analysis outputs and inserts `analytics.customer_rfm`. Power BI reads SQL analytics tables, with shared dimensions for the order facts; product-event metrics remain a separate descriptive comparison. Aggregate CSVs and an offline report are additional review outputs.

SQL staging contains all original columns, including sensitive and IP-like values; restrict access. Analytics tables exclude names, email, password, street and IP-like identifiers. SQL Server and Power BI steps require a connected SQL Server and Power BI Desktop. Financial amounts are loaded as FLOAT to align with the source/Python tolerance checks; for production accounting, use validated DECIMAL precision and agreed rounding rules.
